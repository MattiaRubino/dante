# Contributing

## Branching

- `main` contains approved, stable project decisions and code.
- Work is performed on short-lived branches.
- Initial foundation branch: `docs/project-foundation`.
- Changes should be reviewed through pull requests before merging into `main`.

## Commit style

Use concise imperative commits, for example:

- `docs: define product vision`
- `docs: record frontend architecture decision`
- `feat: add activity creation flow`
- `fix: prevent schedule version conflict`

## Secrets

Never commit API keys, OAuth secrets, signing certificates, production configuration, personal data, uploaded files, or database backups.
