# 4. High-risk pair regressions

## Session vs Actual

**DISTINCT — PASS.**

Session represents one logically continuous execution episode.
Actual represents overall realization of an intended/expected subject.

One Activity may have multiple Sessions and one broader Actual.
An Event may have Actual occurrence without an artificial Session.

No merge justified.

## Milestone vs Outcome vs Evidence

**DISTINCT — PASS WITH HARDENING.**

```text
Outcome
= result/disposition of a specific realization

Evidence
= contextual use of information in an evaluation

Milestone
= meaningful checkpoint whose attainment matters in broader Goal/Plan context
```

Milestone attainment must remain explainable from Evidence/evaluation and must not become duplicate Actual/Outcome truth.

## Occurrence vs Actual

**DISTINCT — PASS.**

Occurrence identifies an expected generated instance.
Actual records how that expectation resolved.

No Actual does not erase the Occurrence and does not imply non-performance.

## Schedule vs Session vs Actual

**DISTINCT — PASS.**

```text
Schedule = accepted temporal assignment
Session  = actual execution episode
Actual   = realization/reconciliation
```

A scheduled time passing does not create Session or Actual.

## Recurrence vs Actual

**DISTINCT — PASS.**

Completion-relative Recurrence may use a qualifying Actual/fact as anchor without owning reality semantics.

Retroactive correction of the qualifying anchor may recompute future expectations while preserving materialized Occurrence/history identity.

No recurrence hardening beyond the existing v0 rules is required.

## Observation vs Quantity/Register

Current semantic distinction remains coherent but final confirmation is deferred to Data / Subjects.

```text
Observation = contextual measurement/assertion record
Quantity    = reusable value + unit semantics
Register    = longitudinal organization/analysis
```

**PASS WITH DEFERRED DEPENDENCY.**

# 9. Asserted reality vs established Actual

The full three-cluster regression exposes a critical epistemic boundary.

Example:

```text
caregiver: medication taken
patient: medication not taken
smart dispenser: unopened
```

These are source assertions/Observations with independent Provenance.

LifeOS must not automatically create three canonical Actuals or select the newest assertion.

Canonical hardening:

> **Reported/asserted reality != established Actual. Actual expresses the currently established realization in context; assertions may conflict and remain unresolved until applicable reconciliation/authority/policy establishes a result.**

This strengthens rather than replaces Actual/Observation/Provenance.

---

# 10. Milestone attainment hardening

Milestone survived its strongest redundancy challenge.

```text
Event: exam
Actual: exam occurred
Observation: 78/100
Outcome: passed
Evidence: pass result supports checkpoint
Milestone: certification checkpoint attained
```

Canonical hardening:

> **Milestone attainment is backed by Evidence/evaluation and must not be modeled as an independent duplicate source of actual reality.**

Milestone retains contextual checkpoint identity and history.

# 11. Multi-actor three-cluster regression

Representative scenarios:

1. shared meeting + actor-specific attendance;
2. shared Activity + several performers;
3. shift hand-off with planned worker != actual worker;
4. caregiving with subject != recorder != source != confirmer;
5. external participant with no Account;
6. private source fact -> shared availability projection;
7. conflicting reports from actors/providers;
8. one actor confirms a version later corrected;
9. access revocation preserving historical attribution;
10. AI reasoning with private multi-party context.

The model does not require per-user copies of Event, Occurrence, Actual, Outcome, Observation, Evidence or Provenance.

Preferred direction remains:

```text
shared canonical object/fact where genuinely shared
+
actor-scoped participation/state/relationships
+
selective visibility
```

**Result:** PASS WITH DEFERRED RELATIONSHIP/ACTOR DEPENDENCIES.
