# 2026-08-16 — Contribution downstream integration

Contribution v0 introduces a specific actor-scoped relation for materially meaningful **actual** input/work. Activity identity remains unchanged.

## Current canonical boundary

```text
Activity
= actionable intention / work-or-behavior unit

Contribution
= actor-scoped materially meaningful actual input/work
  within a bounded realization/result/output context
```

Therefore:

```text
Activity != Contribution
Activity creator/requester != Contributor by default
responsible Actor != Contributor by default
expected performer != Contributor by default
Participant != Contributor by default
Actual performer != complete Contribution attribution universally
```

A real Activity may be performed and may yield one or more Contributions, but Contribution must not be encoded by manufacturing synthetic Activities for every contributor.

## “Contributes to Goal” language

Existing language that an Activity or Plan contributes/supports a Goal concerns contextual support/evaluation semantics. It does **not** establish the actor-scoped Contribution relation.

```text
Activity supports Goal
→ planning / Criterion-Evaluation semantics where applicable

Actor materially contributed actual input/work
→ Contribution
```

## Intention versus actuality

```text
planned contribution
requested contribution
assigned contribution
expected performance
```

do not establish Contribution merely because an Activity exists. Contribution is grounded in actual materially meaningful input/work.
