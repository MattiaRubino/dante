# 2026-08-16 — Downstream closure: Verification v0

Verification v0 resolves the historical `Verification / comprehension` deferred pressure without creating a new kernel primitive.

Canonical result:

```text
Criterion
= contextual evaluative specification

Evidence
= materially relevant evaluative information/use

Evaluation
= application of applicable Criterion state to relevant Evidence/context

Verification
= bounded purpose/profile of that Evaluation
```

Therefore:

```text
Verification != Criterion
Verification != Evidence
Verification != Confirmation
Verification != Acknowledgement
Verification != comprehension
Verification != Decision / Approval
Verification != Authority
Verification != Actual / Outcome
Verification != Provenance
Verification != Conditional Policy
```

`Verification` is canonical vocabulary because the purpose is meaningful and recurring, but it does not introduce a second evaluation engine, universal `VerificationResult` object or validation root.

## Assessment and truth boundary

```text
verified-for-purpose != universal truth
```

A Verification assessment says that the applicable Criterion/Evidence basis supports a bounded assessment for the stated purpose/context. It does not rewrite source reality, establish every embedded claim as true, or make the target's owning domain state automatically effective/current.

## Missing and conflicting Evidence

Existing Criterion/Evaluation epistemic rules remain fully applicable:

```text
no Evidence != failed Verification
insufficient Evidence may remain unknown / indeterminate
conflicting Evidence may remain unresolved
```

No universal newest/provider/user/AI/highest-confidence winner is introduced.

## History and material state

Where consequential, Verification remains reconstructible against the material target, Criterion and Evidence/source states actually used.

```text
Verification V1 under target S1 + Criterion C1
later target S2 or Criterion C2 materially changes
→ V1 remains historical about S1/C1
→ no silent carry-forward
```

Later source correction may change current evaluation without erasing historical basis.

## Multi-Actor / Visibility

Verifier is a contextual Actor role and may differ from subject, recorder, Evidence selector, represented party and Authority holder. External/accountless verifiers remain representable.

Private Evidence may support an authorized bounded Verification result without forcing disclosure of the Evidence itself. Evaluation-result Visibility and Evidence/source Visibility remain independently governed.

## Conditional Policy boundary

An applicable Conditional Policy may consume a Verification-purpose Evaluation result as activation basis, but:

```text
Verification assessment != Conditional Policy
Verification assessment != downstream response
```

## Comprehension remains separately deferred

The historical combined label `Verification / comprehension` is now split by downstream evidence:

```text
Verification   RESOLVED through Criterion/Evaluation semantics
comprehension  STILL SAFE DEFERRED
```

Comprehension/check-understanding remains owned by a future common-ground/cognitive-state review and is not manufactured from Evaluation, Confirmation or Acknowledgement.
