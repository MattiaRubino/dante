# 2026-08-15 — Resource Allocation boundary

Resource Requirement / Allocation v0 confirms that selecting a Person as Resource provider does not establish Participation.

```text
Resource Allocation
= planned provider designation

Participation
= intended/response or Actual involvement in a bounded shared occurrence/interaction
```

Therefore:

```text
Allocation != Participation
allocated Person != participant automatically
```

Example:

```text
Requirement: qualified interpreter
Allocation: Anna
```

does not imply:

```text
Anna invited
Anna accepted
Anna will participate
Anna actually participated
```

A shared workflow may separately create Participation semantics when the Person is expected/invited to be involved. Actual Participation remains independently established from response/intention and independently from Allocation.

Reallocation does not rewrite Participation history. Conversely, a participant substitution/attendance change does not automatically establish a new Resource Allocation unless a real planning designation occurred.

Provider-specific attendee vocabulary remains non-authoritative for LifeOS ontology: room/equipment/resource booking does not turn non-human Resources into LifeOS Participants.

Participation v0 remains **PASS WITH HARDENING, REOPEN = 0**.
