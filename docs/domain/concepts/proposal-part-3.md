# 2026-08-16 — Proposal / Possibility boundary

Possibility v0 adds a bounded pre-commitment candidate-future semantic. It does not broaden or replace Proposal.

Canonical separation:

```text
Possibility
= retained candidate future that remains open
= no proposing act required
= no recipient/consideration context required

Proposal
= Actor puts a materially specific candidate action/state/term/rule/option/change
  forward for consideration in a bounded context

Possibility != Proposal
```

Representative chronology:

```text
T0 A privately keeps "maybe move the holiday to September" as Possibility P1.
T1 A explores cost/availability.
T2 A sends the materially specific September option to B for consideration.
T3 Proposal PR1 now exists and may reference/derive from P1.
```

Required interpretation:

```text
P1 != PR1
T0–T1 were not historical Proposal state
same candidate wording != same semantic act
```

A Possibility may never be proposed. A Proposal may be created directly without a previously persisted Possibility.

## Shared/system boundary

```text
AI/system surfaces Possibility
!= Proposal by an Actor automatically

shared Possibility
!= Proposal automatically

recipient sees Possibility
!= Proposal / Request / Acknowledgement / Agreement / Decision automatically
```

If an Actor or authorized system actually performs a Proposal semantic act, existing Proposal attribution/Representation/Authority rules apply.

## Dismissal / selection boundary

```text
Possibility dismissed
!= Proposal rejection automatically

Proposal rejected
!= Possibility permanently impossible
```

The relevant semantic owner retains its own history.

Proposal v0 remains **PASS WITH HARDENING; REOPEN = 0**. No Proposal lifecycle, Agreement/Consent, Decision, Request, Resource Allocation or Authority invariant is reopened.
