# 2026-08-16 — Living Referent language alignment

## New canonical kernel term

```text
Living Referent
→ scoped native identity for an individually tracked non-human living organism/specimen
→ use only where individual identity materially matters over time
```

## Bounded product/profile vocabulary

```text
Pet
Animal
Plant
Tree
Bonsai
Companion animal
Specimen
```

may be natural UI/profile/kind vocabulary. They do not automatically establish separate kernel roots.

## Rejected semantic expansions

```text
LivingThing
BiologicalEntity
ManagedObject
Thing
```

must not be introduced as universal semantic roots merely to unify Person, Asset and Living Referent.

## Identity guardrails

```text
name != Living Referent identity
species != Living Referent identity
breed != Living Referent identity
cultivar/variety != Living Referent identity
microchip/tag/provider ID != canonical Living Referent identity
owner/caregiver/location != Living Referent identity
```

## Existing term boundaries retained

```text
Person
→ native human identity

Asset
→ scoped native individually tracked non-human physical-object identity

Subject
→ contextual aboutness role; not identity

Resource
→ contextual planning/execution role/capability; not identity
```

Therefore:

```text
Person != Living Referent != Asset
Living Referent != Subject
Living Referent != Resource
```

The exact product/UI label may vary by profile. The semantic distinction must remain reconstructible even if a future logical implementation uses common technical references.
