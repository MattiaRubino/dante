# 2026-08-16 — Possibility language alignment

## New canonical kernel term

```text
Possibility
→ scoped persistent candidate-future / pre-commitment semantic
→ use when a materially relevant future candidate is retained while still open
  before intentional Goal adoption / Decision / execution commitment
```

## Existing canonical boundary

```text
Goal
→ intentionally adopted desired outcome/condition/change/pattern

Proposal
→ Actor puts a materially specific candidate forward for consideration

Decision
→ bounded resolution

Plan
→ execution strategy/coordination

Activity
→ directly executable intended action

Content Artifact
→ persistent reusable information-content identity
```

Therefore:

```text
Possibility != Goal
Possibility != Proposal
Possibility != Decision
Possibility != Plan
Possibility != Activity
Possibility != Content Artifact
```

## Bounded product / natural-language vocabulary

```text
Idea
Someday
Maybe
Aspiration
Opportunity
Bucket list
Wishlist
Save for later
```

may be natural product/UI vocabulary. They do not automatically establish separate kernel roots.

Interpret by actual semantics:

```text
Idea as reusable information/content
→ Content Artifact may suffice

Idea/aspiration as retained candidate future before adoption
→ Possibility

intentionally adopted desired future
→ Goal

material candidate put forward by an Actor for consideration
→ Proposal

resolved alternative/question
→ Decision
```

`Someday` / `Maybe` are especially unsuitable as identity roots: they are product/query/lifecycle language and may surface more than one already-owned semantic family.

`Opportunity` remains specialist/product vocabulary unless a bounded domain supplies its own justified semantics. CRM Opportunity does not become universal LifeOS ontology.
