## 1.1 What survives the matrix

No analytical dimension is universal.

The strongest cross-World invariants are instead:

```text
ORIENTATION
CONTINUITY / ability to resume
NEXT when something has a next state
EVIDENCE / ability to understand basis/history
EXPLORE
ACT / DECIDE when authority/capability exists
```

`Situation`, `Attention` and `Change` are highly general but legitimately absent in some states.

`Trajectory` is explicitly non-universal.

This is important because a product that starts by designing `Metric / Trend / Goal / Time Filter` would optimize around the least universal layer.

# 2. Time Lens falsification matrix

Question:

> Would a single World-level time range meaningfully and consistently control the most important first-screen outputs?

| World | Result | Why |
|---|---|---|
| Music | FAIL as universal | current release, next milestone, recent Sessions and performance history have different time orientation |
| Travel | FAIL | trip-relative future/now is stronger than generic trailing time window |
| Finance | PARTIAL | useful for analysis, but current situation/reconciliation/upcoming obligations may not share it |
| Study | PARTIAL | history/assessments can share time; next exam/current plan often should not |
| Body | PARTIAL | some observed trends share range; current plan/schedule may not |
| Relationships | FAIL | forcing trailing period risks turning context into engagement analytics |
| Vehicle | FAIL/PARTIAL | maintenance deadlines/current condition/history have different scope |
| Shared work | PARTIAL | updates/history may use time; milestones/blocked work do not need same window |
| Care | FAIL/PARTIAL | current care state and upcoming actions outrank historical filter |
| Photography | FAIL | opportunity/next shoot/edit continuity is not trailing-window-first |
| Unknown | FAIL by default | semantics cannot be assumed |

**Cross-case verdict:** temporal scope is a contextual analytical/query capability, not a universal World organizing control.

# 4. Core inference from the borderline corpus

A World is **not created by entity type**.

The same canonical owner may or may not justify a World depending on user-recognizable continuity value.

Therefore automatic rules such as these are rejected:

```text
Goal -> World
Project -> World
Person -> World
Asset -> World
Calendar -> World
Domain category -> World
```

Possible future DANTE behavior:

```text
DANTE detects repeated contextual continuity
-> may propose creating/pinning a World
-> user accepts/rejects
```

A proposal must not silently create taxonomy or move canonical ownership.

# 5. World proliferation stress

## Problem

If every meaningful thing becomes a World, Home/Mondi degenerates into a second file tree or project list.

Example user reality:

```text
Music
Photography
Finance
Health
Work
Family
Car
House
English
Japan Trip
Album A
Album B
Song 1
Song 2
Side project
Job search
Gym
Reading
...
```

A system that automatically makes each item a World creates cognitive fragmentation rather than reducing it.

## Product rule

Worlds are **curated continuity entry points**, not exhaustive containers.

Strong default posture:

```text
few readily recoverable Worlds on Home
+
more contexts available through Mondi management/search
+
ordinary objects remain ordinary objects
```

No arbitrary numeric maximum is frozen here.

The product should optimize for recognizability and recovery cost, not sphere count.

---

# 6. Overlap stress — Worlds are allowed to overlap

Example canonical reality:

```text
Trip to Iceland for astrophotography
```

May appear in:

```text
Travel World
Photography World
Finance World (cost projection)
Family World (shared commitment)
```

Correct:

```text
one canonical Event/Plan/Activity/Artifact/etc.
+
several bounded projections
```

Wrong:

```text
copy trip record into four World containers
```

Implication:

`World membership` must not become an accidental ownership model.

A projection may have contextual inclusion rules/configuration while source identity remains canonical elsewhere.

---

# 7. Nested World stress

Example:

```text
Music
  Album A
    Song X
```

Do not assume this requires nested World hierarchy.

Possible product choices:

```text
Music World
-> Album A as prominent continuity/module/Explore context
-> Song X as artifact/project detail
```

or, if user repeatedly needs Album A as an independent entry point:

```text
Music World
Album A World
```

Both may project the same canonical realities.

**Current verdict:** do not introduce parent/child World ontology or navigation tree until real use proves it necessary.

# 8. World lifecycle stress

Finite and persistent Worlds require presentation lifecycle without rewriting source history.

Potential product-level states for future configuration, not Domain concepts:

```text
EMERGING
ACTIVE
DORMANT
COMPLETED_CONTEXT
ARCHIVED / UNPINNED
```

These names are not frozen.

## Emerging

Sparse new context. First screen may mostly orient and provide valid next setup/import actions.

## Active

Frequent continuity and current material.

## Dormant

Still meaningful, little recent activity. No guilt framing and no automatic deletion.

## Completed context

Finite reality is over but history/artifacts/outcomes remain useful.

## Archived/unpinned

Removed from prominent continuity access. Canonical reality remains intact.

Critical invariant:

```text
remove/archive World presentation != delete canonical reality
```

# 9. Re-entry interval stress

The first-open job changes depending on how long the user has been away.

## Returned after minutes

Priority:

```text
resume current interaction
preserve selection/navigation
avoid redundant recap
```

## Returned after a day

Priority:

```text
what changed
what is next
resume
```

## Returned after weeks/months

Priority:

```text
orientation
meaningful changes
current active state
what is worth resuming
```

Implication:

A future resolver may need a `reference point` concept for Change/catch-up, but should not equate it mechanically with `last page visit` if that creates meaningless noise.

No backend contract is frozen here.

---

# 10. Negative-space stress — what if the correct answer is “nothing”? 

A strong World must tolerate:

```text
nothing needs attention
nothing changed materially
no valid trajectory
no upcoming event
no AI insight
```

Correct UI:

- simply omits low-value sections;
- may show calm current continuity;
- does not manufacture content to appear intelligent.

DANTE product quality is partly measured by knowing when **not** to produce an answer.

---

# 11. Ranking pressure — when many answers are available

Suppose Music has simultaneously:

```text
3 active tracks
1 upcoming release
2 new imported performance changes
12 recent Sessions
5 artifacts
1 blocked collaborator review
1 DANTE opportunity
```

The first screen should not equal all available projections.

Provisional ranking dimensions:

```text
user-stable/pinned importance
immediacy / time sensitivity
material consequence
resumability value
meaningful change since reference point
explicit user intent/current selection
confidence/provenance quality
novelty only as a weak tie-breaker
```

Hard reject:

```text
AI relevance score alone decides composition
```

Adaptive ranking must be inspectable enough to avoid mysterious page reshuffling.

# 12. First-screen density stress

## 0 meaningful outputs

Orientation + truthful empty/emerging state.

## 1–2 meaningful outputs

Use space confidently. Do not pad.

## 4–8 meaningful outputs

Likely normal rich World. Strong hierarchy required.

## 12+ meaningful outputs

First screen remains bounded. Lower-value material becomes Explore or deeper sections.

## 20+ potential modules

This is a composition catalogue problem, not permission to render 20 cards.

**Result:** density budget should be driven by answer priority and visual hierarchy, not registry size.

# 13. Home ↔ World duplication stress

Example:

Home already shows:

```text
meeting in 20 min
release at risk
car document expires soon
```

Opening Music should not merely repeat the Home warning as an identical card.

World adds scoped value:

```text
why release is at risk
what changed
which artifact/review blocks it
what can be resumed/decided
```

Rule:

```text
Home = cross-life compression
World = scoped expansion/continuation
```

The same fact may appear at different information altitude without canonical duplication.

---

# 14. Search ↔ World stress

Search answer:

> “Where is the latest master of Black Cat?”

Search can resolve directly to artifact/detail.

It should not force entry through Music World.

World is valuable when user intent is contextual:

> “Take me back into Music.”

or:

> “What is going on with my music projects?”

Rule:

```text
known exact target -> direct detail can be best
context recovery/exploration -> World can be best
```

---

# 15. DANTE AI ↔ World stress

User asks globally:

> “Can I realistically add a photography trip next month?”

DANTE may need cross-life orchestration; this is **not** purely Photography World intelligence.

Inside Photography World:

> “Which shoot should I finish first?”

World-scoped context is appropriate.

Rule:

```text
World scope must never trap DANTE when the question materially requires cross-life reasoning
```

A contextual surface may escalate to broader orchestration with explicit scope change.

- it forces the first real projection contract and module rendering around an actual user job.

# 17. Falsification verdict

The provisional definition survives the deeper matrix:

> **A World is a user-recognizable continuity context for a significant part of reality. World Focus helps the user understand that context and continue from where things stand.**

It survives:

```text
broad + narrow scopes
finite + persistent scopes
quantitative + qualitative scopes
single-owner-centered + heterogeneous scopes
personal + multi-actor scopes
active + dormant + completed scopes
sparse + dense scopes
AI available + unavailable
provider fresh + stale
same reality projected in multiple Worlds
```

The main product hardening remains:

> **World is an optional curated continuity entry point, not an automatic classification of canonical reality.**

---

# 18. Gate conclusion

WR0 can move to user product review with the following candidate truths:

```text
WORLD != dashboard
WORLD != folder
WORLD != life-area ontology
WORLD != automatic Goal/Project/Asset wrapper

WORLD = curated continuity context

WORLD FOCUS JOB
= understand this part of my life and continue from here

FIRST SCREEN
= sparse ranked answers to meaningful questions
not a filled widget grid

GLOBAL TIME LENS
= contextual/conditional, not universal first-screen control

HOME
= cross-life compression/orientation

WORLD
= scoped expansion/recovery/continuation
```

No implementation beyond B1 should resume until these are reviewed by the user.
