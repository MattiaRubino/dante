# 1. Final thesis

The universal work-semantic layer is intentionally smaller than the old discovery vocabulary.

```text
L1 != all World content
L1 != all module kinds
L1 != all Output Grammar families
L1 != Domain wrapper layer
L1 != renderer catalog
```

L1 exists only for reusable derived user-work semantics that recur across materially different Worlds, are not already owned by Domain, do not belong to L2–L8, remain meaningful across renderer changes, remain useful without DANTE, and cannot be deleted/merged without recurring semantic loss.

A valid World answer may use **zero L1 primitives** when direct typed Domain/application projections already preserve the user job.

Final finite catalog:

```text
WP-01 CONTINUITY
WP-02 ATTENTION
WP-03 COMPARISON
WP-04 TRAJECTORY
```

No fifth universal L1 primitive survived deletion/merge pressure.

# 3. Common primitive contract

All four WP primitives are application-derived projections, never canonical owners.

```text
primitive projection != canonical truth
primitive ref != NativeRef automatically
primitive result != authorization
primitive visibility != permission
primitive result != durable DANTE memory
primitive result != accepted effect
primitive result != persisted source copy by default
```

Common rules:

- explicit typed source/projection references only;
- L2 basis/freshness/validity/integrity attached where material;
- L3 recipient/purpose disclosure resolved upstream;
- truthful absence is valid;
- missing/unknown never becomes false/zero/completed;
- basis/revocation/redaction can invalidate a current derived projection;
- stable pinning stores config/spec/reference, not accidental source truth;
- no raw DOM, React state, provider credentials, AuthZ decision or arbitrary untyped context bag;
- DANTE may consume/explain a primitive but does not make it exist.

L1 primitive identity is not a mandatory durable Domain identity. A deliberately frozen historical artifact is an explicit source/history capability, not automatic primitive persistence.

# 4. WP-01 — Continuity

> **Continuity is a bounded work projection of one or more materially resumable threads that preserves the meaningful current/unfinished state, the last meaningful checkpoint and the truthful seam through which work can continue when such a seam exists.**

Question:

> **What is genuinely in motion here, where did it meaningfully stop, and what can I truthfully resume?**

Required grounding, where applicable:

```text
recognizable thread/target ref
material current or unfinished state
meaningful checkpoint/basis
continuation destination/intent when one truly exists
```

A blocked thread can remain Continuity while the blocker independently produces Attention.

Hard non-collapses:

```text
recent != resumable
last viewed != meaningful checkpoint
open != in motion
unfinished != important
blocked != automatically urgent
AI-mentioned != continuity fact
Continuity != Activity / Plan / Session / Schedule
Continuity != generic recent-items list
```

Useful composition:

```text
Continuity + Attention   blocked resumable work
Continuity + Comparison compare current thread with prior checkpoint
Continuity + Domain     resume a Plan/Activity/artifact without replacing its identity
```

DANTE may summarize/explain or prepare continuation. It may not invent resumability or a destination.

B2 already provides the real bounded Continuity vertical and permanent semantics. WS6 accepts that direction; the current B2 TypeScript shape is not declared the final universal WP-01 schema.

# 5. WP-02 — Attention

> **Attention is a bounded work projection of materially unresolved matters that warrant user awareness or response now/soon because of consequence, blockage, risk, inconsistency, deadline or another explicit application-grounded reason.**

Question:

> **What requires my attention here, why does it matter, and what kind of response or resolution is actually pending?**

Grounding may include:

```text
matter/affected target ref
attention reason/basis
material consequence/impact
pending response/resolution kind
relevant timing/basis when material
```

Hard non-collapses:

```text
Attention != notification
Attention != unread state
Attention != inbox item
Attention != generic priority score
read != resolved
dismissed != resolved
snoozed != resolved
acknowledged != resolved
AI-high-score != attention fact
```

Useful composition:

```text
Attention + Continuity   blocked resumable work
Attention + Comparison   conflict/options needing response
Attention + Trajectory   trajectory/threshold produces a grounded matter
Attention + Domain       Dependency/Request/Decision/resource state remains upstream
```

A `review queue` is a bounded view/composition over Attention, not another primitive.

DANTE may explain basis, compare responses or prepare action. It may not manufacture urgency or semantic resolution.

# 6. WP-03 — Comparison

> **Comparison is a bounded alignment of two or more materially comparable projections, alternatives or basis states across explicit dimensions so the user can understand differences, deltas or trade-offs without converting the comparison itself into a Decision, Proposal or canonical state.**

Question:

> **How do these bounded alternatives/states differ under an explicit basis, and what is or is not meaningfully comparable?**

Required semantics, as applicable:

```text
2+ explicit compared refs/projections
bounded comparison question/purpose
explicit dimensions or typed comparison basis
baseline/reference member when applicable
missing / unknown / incomparable states
L2 source/material basis when material
```

It must be legal to return partial comparability or insufficient basis without inventing a winner.

Reusable compositions:

```text
Change
= Comparison(fromBasis, toBasis)

Planned vs Actual
= Comparison(planned projection, Actual/Session/outcome projection)

Decision preparation
= Domain decision question/candidates
+ Comparison
+ L2 evidence/basis
+ optional Criterion/Evaluation
```

Hard non-collapses:

```text
Comparison != Decision
Comparison != Proposal
Comparison != recommendation automatically
Comparison != ranking automatically
Comparison != reconciliation winner
Comparison != source precedence
Comparison != one scalar score
Comparison != proof of causality
```

Comparison is not expanded into a time-series mega-object merely to reduce the primitive count. When comparing trajectories, compare explicit Trajectory projections.

DANTE may explain trade-offs or simulate over authorized inputs; it may not silently change dimensions/baseline or create an accepted Decision/effect.

# 7. WP-04 — Trajectory

> **Trajectory is a bounded ordered projection of a materially meaningful value, evaluation or typed state over an explicit axis/window, preserving order, basis, missingness and aggregation semantics so evolution can be understood without implying causality or universal progress.**

Question:

> **How has this bounded facet evolved across the relevant ordered basis, with what gaps/aggregation and under what interpretive limits?**

Time is the common axis but not a mandatory World-level container.

Required semantics, where applicable:

```text
subject/facet/projection ref
ordered axis/window
ordered points/intervals/evaluations
value/unit or typed evaluation semantics
aggregation/downsampling basis
missingness/coverage
L2 source/material basis
```

The application preserves material distinctions such as point measurement vs interval/flow aggregate, count/rate, Criterion/Evaluation result, or another typed ordered state.

Hard non-collapses:

```text
Trajectory != universal Register
Trajectory != Observation source truth
Trajectory != time as World container
Trajectory != Goal progress automatically
Trajectory != causality
Trajectory != prediction
missing interval != zero
trend != confirmed preference
correlation != cause
```

Goal progress appears only when authoritative Criterion/Evaluation semantics justify it.

Trajectory remains separate from Comparison because ordered-axis/window, missing intervals, point-vs-interval meaning and aggregation/downsampling are material semantics. Absorbing all of them into Comparison would create an analytics mega-object.

Useful composition:

```text
Trajectory + Attention   material evolution creates a grounded matter
Trajectory + Comparison  compare periods/baselines/subjects/trajectories
Trajectory + Domain      Observation/Session/Actual/Outcome/Evaluation stay sources
```

DANTE may explain patterns with explicit limits. It must not fabricate missing points, causal claims, diagnosis or Goal progress.

# 10. Minimality proof

Deletion pressure:

```text
remove WP-01 -> recurring resume/checkpoint jobs lose semantics
remove WP-02 -> unresolved matter collapses into state/notification
remove WP-03 -> change/trade-off/planned-vs-actual becomes ad hoc per vertical
remove WP-04 -> ordered series semantics leak into renderer or Comparison
```

Pairwise merge pressure:

```text
Continuity + Attention   REJECT -> resumable != unresolved
Continuity + Comparison  REJECT -> checkpoint/resume != contrast
Continuity + Trajectory  REJECT -> qualitative continuity need not be metric/ordered series
Attention + Comparison   REJECT -> unresolved consequence != contrast
Attention + Trajectory   REJECT -> attention need not arise from a series/threshold
Comparison + Trajectory  REJECT -> unordered alternatives != ordered-series semantics
```

A generic `WorkItem`, `AnalyticProjection`, `WorldData` or arbitrary payload wrapper is rejected because it would erase the semantic boundaries WS1–WS5 spent multiple cycles proving.

The system explicitly permits `L1 = none` for scenarios whose useful semantics live entirely in Domain/L2–L8.

```text
DANTE unavailable != primitive unavailable
DANTE result != source truth
```
