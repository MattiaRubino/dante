# LifeOS Logical Model — Integrated A+B+C+D Mechanism Benchmark v1

**Verified:** 2026-08-17  
**Scope:** cumulative identity/reference + intention/execution + time/reality + evidence/knowledge/history

## 1. Trigger

Integrated replay found four hardenings:

```text
knowledge-current != applicable-now
unknown applicability must remain representable
not-current != irrelevant forever
point Observation/inference != continuing canonical state
```

These pressures materially increase the attractiveness of bitemporal/history-first architectures and therefore trigger LM-WF-21.

## 2. Reopened mechanisms

```text
A Layered Typed model + heterogeneous history implementation
B Universal bitemporal Fact/State table
C Universal event/immutable assertion ledger
D Fully owner-specific independent history
E Global knowledge/statement graph
```

## 3. Bitemporal pressure

Valid-time / transaction-time systems are useful for separating:

```text
when a state applies in represented reality
when a database/system learned or stored it
```

LifeOS disposition:

```text
BORROW / RETAIN AS PHYSICAL INGREDIENT
```

But bitemporality alone does not decide:

- semantic owner identity;
- material-state equivalence;
- unknown applicability;
- Evidence relevance;
- Confirmation/Acknowledgement scope;
- current accepted interpretation under conflict;
- Visibility;
- current-query historical relevance.

Therefore:

```text
valid time + transaction time
!= complete LifeOS epistemic/history model
```

## 4. FHIR applicability pressure

FHIR Condition demonstrates specialist separation among condition identity, clinical status, onset and abatement; FHIR Observation has an effective time/period for the observed value.

LifeOS disposition:

```text
BORROW
historical record != current applicability
effective time != recorded time
point Observation != continuing condition automatically

REJECT
universal clinical status vocabulary across LifeOS
```

## 5. Knowledge graph pressure

Statement/claim graphs can represent qualifiers, sources and competing values well.

LifeOS disposition:

```text
RETAIN FOR BOUNDED ASSERTION/SEARCH/PROJECTION USE
REJECT AS UNIVERSAL DOMAIN SOURCE OF TRUTH
```

The new `knowledge-current vs applicable-now` distinction strengthens rather than weakens this rejection: a generic statement rank/current flag cannot safely encode all owner-specific epistemic/applicability semantics.

## 6. Event/immutable ledger pressure

Immutable ledgers remain excellent for chronology/audit/time-travel.

They still do not determine whether one assertion became the current owner state, whether a condition applies now, or whether historical information is relevant to a new query.

```text
chronology != semantics
```

## 7. Owner-specific history pressure

Owner-specific history remains valuable for integrity and domain fit. Integrated A+B+C+D still requires common query/state-binding contracts to avoid incompatible per-owner semantics.

## 8. Verdict

```text
SELECTED
A Layered Typed model + ReferenceAddress/MaterialStateRef

MECHANISM VERDICT
RETAIN + HARDEN

UNIVERSAL BITEMPORAL FACT ROOT
REJECTED

BITEMPORAL / EVENT / SNAPSHOT / OWNER-HISTORY TECHNIQUES
RETAINED AS PHYSICAL CANDIDATES/INGREDIENTS
```

## 9. Reopen triggers

Reconsider before Physical Model selection and Whole-Logical closure if measured/query evidence proves one shared history substrate materially improves correctness/performance without creating a false semantic root.
