## FA-02 — Occurrence `explicit_extra` governing-state correction

The primary semantic map currently over-generalizes Occurrence generation by presenting every Occurrence as having an exact governing Recurrence MaterialState.

The executable CP6-M06 contract is more precise:

```text
Occurrence origin = recurrence_generated
→ source_native_ref REQUIRED
→ governing_recurrence_state_ref REQUIRED
→ exact family-compatible generated coordinate REQUIRED

Occurrence origin = explicit_extra
→ source_native_ref REQUIRED
→ governing_recurrence_state_ref MUST BE NULL
→ it must NOT pretend to have been generated by a Recurrence MaterialState
```

Binding corrected model:

```text
Occurrence
├── source Routine/Event
├── origin
│   ├── recurrence_generated
│   │   ├── exact governing Recurrence MaterialState REQUIRED
│   │   └── generation coordinate REQUIRED
│   └── explicit_extra
│       ├── governing Recurrence MaterialState ABSENT by design
│       └── one-off extra-instance provenance preserved
└── later Schedule / Session / Actual / Outcome / Confirmation as applicable
```

Canonical rule:

```text
explicit_extra
!= recurrence_generated with a special flag
```

An explicit extra instance is related to the recurring source while remaining outside the source recurrence generation state.

## FA-03 — Schedule precision must include coarse accepted placement

A Schedule is not limited to exact date-time blocks.

Accepted Schedule semantics can include materially different precision such as:

```text
Tuesday
Tuesday afternoon
Tuesday at 18:00
Tuesday 18:00-20:00
start Tuesday 18:00 / end unresolved
```

Therefore:

```text
coarse accepted placement
!= exact time block
!= all-day/date-span semantics automatically
!= unplaced
!= postponed
```

The implementation roadmap must preserve the accepted semantic precision actually known instead of manufacturing timestamps for UI/database convenience.

## FA-04 — Recurrence pattern anchor and effective range

The primary map contains recurrence families but the final audit makes these additional recurrence dimensions blocking:

```text
pattern anchor / phase
!= effective range
```

A rule such as `every 2 weeks` is incomplete where phase matters unless its anchor is known.

`created_at` must not silently become the semantic recurrence anchor.

Effective range may be:

- open-ended;
- until a temporal boundary;
- for N expected Occurrences.

And:

```text
N expected Occurrences
!= N successful completions
```

## FA-05 — Structural exclusion versus generated-and-skipped

These are distinct histories:

```text
governing recurrence excludes candidate before generation
→ no expected Occurrence exists

Occurrence generated
→ later skipped/cancelled
→ expected Occurrence remains historical truth
```

This affects adherence, analytics, history and explanations.

## FA-06 — Virtual future invalidation versus material history

A future Occurrence with no independent history may remain virtual and be regenerated under a later source policy.

A future Occurrence that already acquired material instance-specific history must not silently disappear because the source recurrence changed.

Material instance history includes, for example:

- accepted Schedule;
- one-off edit;
- skip/cancel disposition;
- provider identity;
- notification/Confirmation state whose history matters;
- Session/Actual;
- another consequential relation.

## FA-07 — Authoring draft is not canonical owner state

Current C1 Simple/Advanced Create shares one draft.

The draft lifecycle is a frontend/application authoring concern:

```text
Create draft
!= Activity
!= Event
!= Routine
!= Schedule
```

Closing/discarding an unsaved draft must not be represented as deleting/cancelling a canonical owner.

If draft recovery/persistence is later introduced, it remains explicit authoring/application state unless a separately authorized operation commits canonical Domain state.
